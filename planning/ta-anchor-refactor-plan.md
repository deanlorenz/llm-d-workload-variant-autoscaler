## §1 Mission & the corrected model (Dean, verbatim)

The binding-analyzer anchor refactor makes saturation-v2 cleanly disable-able AND makes the
ThroughputAnalyzer (TA) enable-able as a standalone analyzer — with **no special voting code**.

Dean's correcting instruction (2026-08-03), verbatim — this is the design contract for PR-1:

> there is (a) and (b). (a) generated by sat; (b) generated by every analyzer including sat. engine
> runs sat. populates anchor with (a) and (b). copies sat as its own analyzer (b) data only if
> enabled. runs every enabled analyzer, any order. each creates its own (b) possibly using the common
> (a) accessible through known anchor. that is the desired end result. Now, copy (b) from first
> analyzer onto anchor.
> The end results passed to optimizer should be the same -- anchor with (a) + (b) -- (b) is the
> default binding analyzer (clearly known if only 1). list with (b) per analyzer.

Consequences, made concrete:

1. **The anchor carries (a) + (b).** (a) = common metadata only sat produces (`AcceleratorName`,
   `Cost`, variant identity/state). (b) = per-analyzer sizing/sort quantities
   (`PerReplicaCapacity`/`TotalCapacity`/`TotalDemand`/`Utilization`). The engine populates the anchor
   from sat's run (getting (a)+(b)), then **copies (b) from the first ballot entry onto the anchor**.
   (a) is **never** overwritten. RC/SC stay per-analyzer off the ballot (§2), never combined onto the
   anchor.
2. **Engine passes the optimizer exactly two things:** the `anchor` and `AnalyzerResults` = the list
   of **enabled** analyzer results. *That list IS the ballot.* There is no forced sat-first entry, no
   name-based skip/append, no conditional sat-v2-vote injection.
3. **All entries on the list vote identically.** No name-checks, no per-analyzer branches. With one
   ballot entry the anchor's (b) already equals that entry's (the copy is a no-op / trivially binding);
   with several (PR-2) the optimizer refreshes the anchor's (b) with the per-role `argmax_i rd_i`
   binding analyzer each iteration. **One code path** — the `len(ballot) > 1` check is a *work-skip*,
   not a code fork, and PR-1 makes **no assumption** that only one analyzer is ever enabled.
4. The three configurations emerge purely from **which analyzers are enabled**, not from any special
   logic: `[sat-v2]` (default, byte-identical to today) · `[TA]` (TA-only) · `[sat-v2, TA]` (both →
   the dynamic multi-vote refresh, **PR-2 only**; PR-1 simply does not build the refresh).

## §2 The (a)/(b) split — why the anchor is required

**Why an anchor is *required*, not merely convenient** (verified on this base):

- `saturation_v2` populates the full topology on each `VariantCapacity`: `AcceleratorName`, `Cost`,
  `Role`, `ReplicaCount` (`internal/engines/analyzers/saturation_v2/analyzer.go:441-446`).
- `throughput` does **NOT** populate `AcceleratorName` or `Cost` — its `VariantCapacity` carries
  `VariantName, Role, ReplicaCount, PendingReplicas, PerReplicaCapacity, TotalCapacity, TotalDemand,
  Utilization, Reason` only (`internal/engines/analyzers/throughput/analyzer.go:372-382`).

So `Cost` and `AcceleratorName` — needed by cost-efficiency ordering (`Cost/PRC`) and GPU accounting
— exist **only** on the saturation result. A non-saturation vote cannot supply them. The anchor
(populated from the always-run sat-v2 result) is therefore the sole source of the (a) common metadata,
and it retains that (a) **unchanged** even when sat-v2's vote is disabled (TA-only). This is exactly
why a TA-only anchor still carries full topology/cost.

**The split — EXACT, field-by-field (implement verbatim; assert in §7).** Every field of both structs
is classified. Verified on `main@9906dac5` (`internal/domain/analyzer.go`); read sites confirmed by
grep of `internal/engines/pipeline/`. **cat.** = category; **anchor?** = does the anchor carry it;
**refresh (b)?** = overwritten from the binding vote when `len(ballot)>1` (PR-2 only — PR-1 always
single-vote). "off ballot" = read per-analyzer from `req.AnalyzerResults[i].Result`, never the anchor.

**Table 1 — `domain.VariantCapacity` (per-variant; the elements of `VariantCapacities`):**

| Field | cat. | anchor? | refresh (b)? | Read site(s) — where the optimizer consumes it |
|---|---|---|---|---|
| `VariantName` | (a) join key | yes (sat's; identical across all votes) | no | the map key everywhere (anchor↔ballot join) |
| `AcceleratorName` | (a) | yes (sat's, never overwritten) | no | `cost_aware_optimizer.go:283`; GPU accounting `engine_v2.go:489,523` |
| `Cost` | (a) | yes (sat's, never overwritten) | no | `cost_aware_optimizer.go:284`; `costEfficiency:234` (Cost/PRC) |
| `Role` | (a) | yes (sat's, never overwritten) | no | role bucketing; `cost_aware_optimizer.go:305` |
| `ReplicaCount` | (a) | yes (sat's, never overwritten) | no | GPU accounting; current-replica reads |
| `PendingReplicas` | (a) | yes (sat's, never overwritten) | no | GPU accounting; anticipated-supply reads |
| `PerReplicaCapacity` | (b) sizing/sort | yes (binding vote's) | yes | `buildCapacityMap`, `allocateForModelPaired`, `costEfficiency:234`, `fairShareCap:421` |
| `TotalCapacity` | (b) sizing/sort | yes (binding vote's) | yes | sizing/observability |
| `TotalDemand` | (b) sizing/sort | yes (binding vote's) | yes | sizing; rescale demand |
| `Utilization` | (b) sizing/sort | yes (binding vote's) | yes | `cost_aware_optimizer.go:302` (decision observability, reads the anchor) |
| `Reason` | (b) sizing/sort (describes PRC) | yes (binding vote's) | yes | `prcForVariant` `analyzer_helpers.go:58` gates `ReasonNoData`/`ReasonError` — read **per-vote** in the combine AND mirrored onto the anchor for the sizing view |

**Table 2 — `domain.AnalyzerResult` (model-level; the anchor is one of these):**

| Field | cat. | anchor? | refresh (b)? | Read site(s) |
|---|---|---|---|---|
| `AnalyzerName` | provenance | yes = `"saturation"` (marks the (a) source) | no | **not a decision input** — do NOT read it as "the binding analyzer"; the anchor is a synthetic carrier, always named for sat-v2 even in TA-only |

| `TotalSupply` | (b) sizing (model) | yes (binding vote's) | yes | not read in the optimizer today; mirror for a coherent binding view |
| `TotalDemand` | (b) sizing (model) | yes (binding vote's) | yes | `rescale.go:544` |
| `Utilization` | (b) sizing (model) | yes (binding vote's) | yes | not read in the optimizer today; mirror for coherence |
| `TotalAnticipatedSupply` | (b) RC/SC family | **no** — off ballot | n/a | consumed by the engine's threshold post-step **upstream** of the optimizer; not an anchor field |
| `RequiredCapacity` | (b) RC/SC | **no** — off ballot | n/a | `cost_aware_optimizer.go:304`; `initRoleState` `analyzer_helpers.go:142` |
| `SpareCapacity` | (b) RC/SC | **no** — off ballot | n/a | `cost_aware_optimizer.go:304`; `initRoleState:143` |
| `RoleCapacities` (map → `RoleCapacity`: `Role`,`TotalSupply`,`TotalDemand`,`TotalAnticipatedSupply`,`RequiredCapacity`,`SpareCapacity`) | (b) RC/SC | **no** — off ballot | n/a | `cost_aware_optimizer.go:309`; `initRoleState:141`; `rescale.go:546` — the whole map and its `RoleCapacity` sub-fields stay per-vote |

**One-line rule the coder can hold in head:** the anchor carries **(a) = sat-v2's topology/identity
(never overwritten)** + **(b) sizing/sort = the binding vote's** (per-variant PRC/TotalCapacity/
TotalDemand/Utilization/Reason + model-level TotalSupply/TotalDemand/Utilization). **RC/SC (the model +
role RequiredCapacity/SpareCapacity/RoleCapacities + TotalAnticipatedSupply) never reach the anchor** —
they are read per-analyzer off the ballot, because the cross-analyzer combine reads every vote.

Because the engine copies the (b) sizing/sort subset from the first ballot entry onto the anchor, the
optimizer's sizing/sort/observability sites keep reading **the anchor** (renamed getter) exactly as
they read `satEntry` today — the anchor's `VariantCapacities` now carry (a) + the binding (b). **No
derived "binding capacities" slice is needed** (Dean: "no derived capacity"). RC/SC alone stay
per-analyzer: the combine helpers already iterate the ballot `s` and read RC/SC per-vote.

**Byte-identity falls out for free** in the default config: enabled set = `[sat-v2]`, so `ballot[0]`
*is* sat-v2 — the (b) copy overwrites the anchor's sat (b) with sat's own (b), a no-op, and the anchor
== the sat result field-for-field. TA-only (`[TA]`) leaves (a) as sat-v2's and sets the anchor's (b)
to TA's. No refresh runs with one vote, so all combine-arithmetic bugs stay dormant (§3).

## §3 Scope & non-goals — what PR-1 does NOT touch

**PR-1 delivers (static, single-vote):**

1. The `anchor` field on `ModelScalingRequest` + engine population: copy sat-v2's result into the
   anchor ((a)+(b)), then overwrite the anchor's (b) sizing/sort subset from `ballot[0]`.
2. `AnalyzerResults` = enabled votes (drop the always-first / effectiveEnabled-exempt sat-v2 special
   case; gate sat-v2 like every other analyzer, default-on).
3. Rename `saturationEntry` → an anchor getter; route topology **and** sizing/sort reads to the anchor
   (the anchor now carries the binding (b)); route RC/SC reads per-analyzer off the ballot.
4. TA-only enablement path + tests; default-config byte-identity guarded by the goldens.

**PR-1 changes ZERO combine arithmetic and builds NO refresh machinery.** All four masked bugs are
combine-only (they only manifest with ≥2 votes) and are **deferred to PR-2**:

- **#1** `allocateForModelPaired` per-replica decrement unit (`k·PRC` uniform across analyzers).
- **#2** `roleAggRemaining` — `max_i` over mixed-unit raw RC.
- **#3** rescale water-fill (`rescale.go:521`) + scale-down tie-break (`sortVariantsForScaleDown`).
- **#5** `fairShareValue` uses `Σ_i` where design wants `max_i` (three lock-step sites:
  `fairShareValue:73`, `fairShareCap:421`, `sortVariantsForScaleDown:168`).

With a single vote, every one of these reduces to the single term — correct by construction. PR-2
generalizes the anchor's (b) to the per-role `argmax` binding, adds the per-iteration dynamic refresh,
and fixes #1/#2/#3/#5 *there*.

**Not a prerequisite:** F1 "pre-analysis extraction" from `wva-analyzer-lifecycle-plan.md` is NOT
needed — sat-v2 always runs, so the anchor's (a) is always present. `wva-analyzer-lifecycle-plan.md`
stays intact; PR-1 needs **no new config gate** — `analyzers[].enabled` (`AnalyzerScoreConfig.Enabled`)
already exists, and the change is only removing sat-v2's engine-loop exemption so it obeys that flag
like every other analyzer. The full Activate/Deactivate lifecycle is out of scope.
